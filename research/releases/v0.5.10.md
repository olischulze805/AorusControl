# AORUS Control 0.5.10

## Settings that apply themselves now show it instead of saying it

The charge limit used to explain itself in three sentences: a permanent line above the slider
saying it applies itself shortly after you let go, then "80 % is being applied" while you
dragged, then "applied and read back" when it finished.

An interface that describes its own mechanism in a fixed label is admitting it cannot
demonstrate it. So it demonstrates it: a small mark beside the value turns while the change is
on its way, shows a tick once the device has confirmed it — gone again a second later — and a
dot in the warning colour if the device refused. Nothing is drawn when nothing is pending, and
the space stays reserved so nothing jumps.

The same pattern was in three places, so the mark is in all three: charge limit, battery saver
and fixed fan speed.

## Quieter cards

Those three status lines now carry only failures, and a line with nothing to say disappears
instead of leaving a gap behind.

The battery saver lost one more sentence: "On · 2 settings" was saying what the switch two
centimetres to its right already said.

Seven pieces of interface text are gone in total, in both languages.

## Fixed

Two documentation comments in the source had been filled with code where prose belonged, left
over from the bulk edit that introduced the second language.

## Verified

Full rebuild in Debug and Release without warnings. Smoke tests, worker process checks and the
layout checks at 720, 1000 and 1600 pixels in both languages all pass. The new mark has its
own picture in the layout check, because an animation that only exists while animating cannot
be verified by a screenshot — it is drawn at full strength by default and fades from there.

Not verified live: a real Windows restart with this version, and waking from suspend.
