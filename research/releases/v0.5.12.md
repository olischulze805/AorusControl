# AORUS Control 0.5.12

## Graphics rules survive a restart

A program set to the RTX in the evening could be back on the Intel chip the next morning.
Another program - on this machine NVIDIA's session service, which copies its own GPU profiles
into Windows' graphics settings at logon - had rewritten the entry before AORUS Control
started. The app read that foreign value as a decision made by hand and left it alone, until a
rule was changed and changed back.

Now a program on the list is always brought to its rule, whoever wrote the value last. To let
Windows decide for a program, remove it from the list or switch the automatic off.

The Windows graphics settings are also watched while the app runs. If another program writes
into them later, a managed program is put back after a second of quiet. Should something keep
resetting the same program - more than three times in a minute - the app stops answering for
that minute and says so, instead of the two rewriting one value at each other forever.

## A log you can switch to detailed

Every graphics change is now always logged with its before and after value and the reason, and
changes made by other programs are logged as such. **Info → Log → Detailed logging** adds each
check's registry value, rule and last write for every managed program, for chasing something
that goes wrong without an error.

## Verified

Release build without warnings, the complete smoke-test suite and the offscreen UI checks at all
supported widths. New tests cover the morning case (a foreign value at start is corrected), an
outside write while running, the stop after repeated rewrites, the automatic being off, and the
registry watch itself against a real, temporary registry key.

Not yet verified live: a real Windows restart with this version. The log will show after the
next one who changed which entry and that the app put it back.
